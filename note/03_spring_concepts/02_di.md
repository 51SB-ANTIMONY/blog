# DI (Dependency Injection, 의존성 주입)

> 이 글에 나오는 IoC, Bean, 어노테이션 같은 용어는 [IoC](./01_ioc.md)와 [Spring Framework](../01_spring/01_spring_framework.md)에서 설명했다.

## 정의
제어의 역전(IoC)을 구현하기 위해 사용하는 방법이다.
객체가 필요로 하는 다른 객체(의존성)를 스스로 `new`로 만들지 않고, 외부(컨테이너)에서 받는다.

> **의존성이란?**
> 클래스 A가 동작하려면 클래스 B를 사용해야 할 때, "A가 B에 의존한다"고 하고 B를 A의 **의존성**이라고 한다.
> 예를 들어 `PostService`가 게시글을 조회하려면 `PostRepository`가 필요하므로, `PostRepository`는 `PostService`의 의존성이다.

> **인터페이스와 구현체란?**
> 인터페이스는 메서드의 이름, 매개변수, 반환 타입만 선언하고 실제 동작 코드는 없는 Java 타입이다.
> 구현체는 `implements`로 인터페이스를 구현해 메서드의 실제 동작을 작성한 클래스다. 하나의 인터페이스에 여러 구현체가 있을 수 있다.
> ```java
> public interface PostRepository {
>     Post findById(Long id);  // 선언만 있음
> }
>
> public class JpaPostRepository implements PostRepository {
>     public Post findById(Long id) {
>         // 실제로 DB에서 조회하는 코드
>     }
> }
> ```

## DI를 쓰지 않은 코드
```java
public class PostService {
    // 구현체를 직접 생성하므로 PostService가 JpaPostRepository에 강하게 묶임
    private final PostRepository repository = new JpaPostRepository();

    public Post find(Long id) {
        return repository.findById(id);
    }
}
```
저장소 구현을 바꾸거나 테스트용 가짜 객체로 교체하려면 `PostService` 코드를 직접 고쳐야 한다.

> **테스트와 가짜 객체란?**
> 여기서 테스트는 작성한 코드가 의도대로 동작하는지 확인하는 코드를 따로 작성해 실행하는 것을 말한다. ([테스트 코드](../08_test/01_test_code_and_given_when_then.md))
> 가짜 객체(Fake)는 테스트에서 실제 구현체 대신 쓰려고 만든 구현체다. 예를 들어 `FakePostRepository`는 데이터를 DB가 아니라 Java의 `Map`에 저장한다.
> 가짜 객체를 쓰면 DB 없이도 `PostService`의 로직만 빠르게 확인할 수 있다.

## DI를 사용한 코드
```java
@Repository
public class JpaPostRepository implements PostRepository { ... }

@Service
public class PostService {
    private final PostRepository repository;

    // 생성자 주입: Spring이 PostRepository 타입의 Bean을 찾아 넣어줌
    public PostService(PostRepository repository) {
        this.repository = repository;
    }
}
```
`PostService`는 인터페이스에만 의존한다. 어떤 구현체가 들어올지는 컨테이너가 결정한다.
테스트할 때는 `new PostService(new FakePostRepository())`처럼 원하는 객체를 직접 넣으면 된다.

> **생성자와 생성자 주입이란?**
> 생성자는 `new`로 객체를 만들 때 실행되는 메서드다. 이름이 클래스 이름과 같고 반환 타입이 없다.
> 생성자 주입은 의존성을 생성자의 매개변수로 받는 방식이다.
> Spring은 `PostService` 객체를 만들 때 생성자 매개변수의 타입(`PostRepository`)을 확인하고, 컨테이너에서 그 타입의 Bean(`JpaPostRepository` 객체)을 찾아 전달한다.
> 생성자가 하나뿐이면 `@Autowired`를 생략해도 Spring이 자동으로 주입한다.

## 주입 방법 세 가지
| 방법 | 코드 | 특징 |
|---|---|---|
| 생성자 주입 | 생성자 매개변수로 받음 | 필드를 `final`로 만들 수 있고, 테스트에서 `new`로 직접 넣기 쉬움. **권장 방식** |
| 필드 주입 | 필드에 `@Autowired` | 코드가 짧지만, 테스트에서 의존성을 바꿔 넣기 어려움 |
| 수정자(setter) 주입 | `setXxx()` 메서드에 `@Autowired` | 실행 중에 의존성을 바꿔야 할 때만 사용 |

```java
// 필드 주입
@Service
public class PostService {
    @Autowired
    private PostRepository repository;
}

// 수정자 주입
@Service
public class PostService {
    private PostRepository repository;

    @Autowired
    public void setRepository(PostRepository repository) {
        this.repository = repository;
    }
}
```

> **@Autowired란?**
> "이 자리에 맞는 타입의 Bean을 찾아서 넣어 달라"고 Spring에 알리는 어노테이션이다.

> **final이란?**
> 필드에 `final`을 붙이면 처음 한 번 값을 넣은 뒤에는 바꿀 수 없다.
> 생성자 주입에서는 생성자에서 값을 넣으므로 `final`을 쓸 수 있고, 실수로 의존성을 바꾸는 코드를 막을 수 있다.

## Lombok으로 생성자 주입 코드 줄이기
Lombok의 `@RequiredArgsConstructor`를 쓰면 생성자를 직접 작성하지 않아도 된다.

```java
@RequiredArgsConstructor  // final 필드를 매개변수로 받는 생성자를 자동으로 만듦
@Service
public class PostService {
    private final PostRepository postRepository;
}
```
생성자를 직접 쓰지 않았지만, 컴파일하면 `public PostService(PostRepository postRepository) { ... }` 생성자가 만들어진다.
Lombok은 [Lombok 어노테이션](../06_spring_boot_code/04_lombok.md)에서 설명한다.
