# REST API

> API, HTTP, 클라이언트와 서버 같은 용어는 [API](./01_api.md)에서 설명했다.

## 정의
REST(Representational State Transfer)는 웹 API를 설계하는 방식 중 하나다.
**자원(resource)을 URL로 나타내고, 그 자원에 할 동작을 HTTP 메서드로 나타낸다.**
REST 방식을 따라 만든 API를 REST API(또는 RESTful API)라고 한다.

> **자원(resource)이란?**
> API가 다루는 대상 데이터다. 블로그 API라면 글, 댓글, 회원이 자원이다.

> **표현(representation)이란?**
> 자원의 상태를 JSON 같은 형식으로 나타낸 것이다. 서버는 DB의 글 데이터를 `{"title":"첫 글","content":"안녕하세요"}` 같은 표현으로 바꿔서 보낸다.
> REST라는 이름은 "자원의 표현을 주고받는 방식"이라는 뜻이다.

## 예시
| 하려는 일 | REST API | REST가 아닌 방식 |
|---|---|---|
| 글 목록 조회 | `GET /api/posts` | `GET /getPostList` |
| 1번 글 조회 | `GET /api/posts/1` | `GET /getPost?id=1` |
| 글 생성 | `POST /api/posts` | `POST /createPost` |
| 1번 글 수정 | `PUT /api/posts/1` | `POST /updatePost?id=1` |
| 1번 글 삭제 | `DELETE /api/posts/1` | `GET /deletePost?id=1` |

REST API에서는 URL이 모두 `/api/posts`(자원)를 가리키고, 무엇을 할지는 HTTP 메서드가 정한다.

## 특징
| 특징 | 의미 |
|---|---|
| 클라이언트-서버 구조 | 클라이언트(화면)와 서버(데이터 처리)의 역할이 나뉜다. 서로 API로만 통신하므로 각자 따로 개발하고 바꿀 수 있다 |
| 무상태(stateless) | 서버는 이전 요청의 정보를 저장하지 않는다. 요청 하나에 처리에 필요한 정보가 모두 들어 있어야 한다 |
| 캐시 가능(cacheable) | 응답에 캐시해도 되는지 표시할 수 있다. 클라이언트는 같은 요청에 저장해 둔 응답을 다시 쓸 수 있다 |
| 계층화(layered system) | 클라이언트와 서버 사이에 다른 서버(로드 밸런서, 프록시 등)가 있어도 클라이언트는 알 필요가 없다 |
| 균일한 인터페이스(uniform interface) | 모든 자원을 URL과 HTTP 메서드라는 같은 규칙으로 다룬다 |

> **무상태의 예**
> 로그인한 사용자만 글을 쓸 수 있다면, 서버가 "이 사용자는 아까 로그인했다"고 기억하지 않는다.
> 대신 클라이언트가 요청마다 헤더에 인증 정보(토큰 등)를 담아 보내고, 서버는 그 요청만 보고 판단한다.

> **로드 밸런서란?**
> 들어오는 요청을 여러 서버에 나눠 보내는 장치나 프로그램이다.

## 장점
- URL만 보고 어떤 자원을 다루는지, HTTP 메서드만 보고 무엇을 하는지 알 수 있다.
- HTTP를 그대로 사용하므로 별도의 도구나 규칙 없이 어떤 언어, 어떤 클라이언트에서든 사용할 수 있다.
- 서버와 클라이언트의 역할이 명확히 나뉘어서, 같은 API를 웹, 모바일 앱 등 여러 클라이언트가 함께 사용할 수 있다.
- 무상태라서 서버를 여러 대로 늘리기 쉽다. 어느 서버가 요청을 받아도 같은 결과를 낼 수 있기 때문이다.

## 단점
- REST는 강제되는 표준이 아니라 설계 방식이라서, 사람마다 URL과 응답 형식을 다르게 만들 수 있다.
- HTTP 메서드가 몇 개로 정해져 있어서, "글 발행", "비밀번호 재설정"처럼 CRUD로 표현하기 애매한 동작을 URL로 나타내기 어렵다.
- 화면 하나에 여러 자원이 필요하면 요청을 여러 번 보내야 할 수 있다. (예: 글, 작성자, 댓글을 각각 요청)

> **CRUD란?**
> Create(생성), Read(조회), Update(수정), Delete(삭제)의 앞 글자를 딴 말이다.

REST API를 만들 때 지키는 규칙은 [REST API 사용 규칙](./03_rest_api_rules.md)에서 정리한다.
